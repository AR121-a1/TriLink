# v0.8：六成员有界自动路由传输底座

2026-09-16。取代 v0.7 固定三节点链序。此版本实现传输层，不等于已完成真实 Room、RGB 应用或实板验收。所有板使用同一固件，MAC 不写死。

## 1. 三张表与自动选路

| 表 | 来源、上限 | 用途 |
|---|---|---|
| 本机直连邻居 | HELLO/心跳发现，6 个，不含本机；2 秒过期 | 判断实际下一跳是否直接可达 |
| 传输成员表 | 显式 CONFIG，1–6 个，包含本机；按 MAC 排序 | 约束转发范围及位图索引；不是入群审批 |
| 拓扑与路由 | 每成员的直连邻居位图、relay 能力、boot/序号、过期时间 | 仅对新鲜且双向确认的边执行 BFS，选最短跳数路径 |

CONFIG 中 MAC 的输入顺序不再决定路径。每个允许 relay 的成员都可中继，无须指定“二号机”，也无须经 leader。链最多 6 个节点、5 条无线链路；菱形/环形连接同样受支持。等长路径按规范化 MAC 顺序打破平局；这不是同时复制业务到多条路径的负载均衡。

路由采用小规模链路状态传播：每个成员约 1 秒发布一条拓扑，按规范化位置增加 31 ms 的周期差；直连状态变化加快下一次更新。控制状态陈旧超过 3500 ms 不参与选路。广播只用于拓扑，业务 DATA/ACK 按计算出的下一跳单播。中间节点必须 relay=1，源/目标自身 relay=0 仍可通信。协议没有全信道扫描、跨信道桥接、IP/VPN 或 PC 网络旁路。

拓扑接收检查 room/epoch、成员指纹、上一跳、visited、boot/序号。重复消息不续期；同一拓扑经更短路径到达时允许有限再次传播，避免先到的绕远路径阻断远端发现。报文带 visited 位图和有限跳数，限制瞬态环路。

离线检测、拓扑传播、队列拥塞和重试共同影响恢复时间，3500 ms 不是端到端收敛保证。无线压力与实际恢复时间仍须实测。

## 2. 格式与身份

外层 200 B 不变：24 B 基础头 + 4 B service 头 + 36 B 路由头 + **最多 132 B 业务数据** + 4 B CRC。

ROUTE service=9，格式版本=2。相对路由头：

| 偏移 | 字段 |
|---|---|
| 0, 4 | room u32、epoch u32，小端 |
| 8, 14 | 原始 source MAC、最终 destination MAC，各 6 B |
| 20, 24 | source boot u32、message u32 |
| 28, 29, 30 | remaining u8、kind u8、payload length u16 |
| 32, 33, 34 | attempt u8、visited u8、reserved 两字节必须为 0 |

kind：DATA=1、ACK=2、TOPOLOGY=3。拓扑载荷是成员表 CRC32（4 B）、邻居位图（1 B）、relay（1 B）。MAC 规范化顺序仅用于位图，不代表加入先后或 leader 继承顺序。CRC 检错和 roster 指纹都不是认证，存在碰撞和冒充风险；仅适用于受控课程实验。

v0.7 空口格式 1 和 TRILINK/2 CONFIG 的链序语义不兼容；新固件显式拒绝旧业务入口。TRILINK/1 HELLO/SEARCH 的 PC 识别格式保留。不要将“旧 PC 识别兼容”理解为新旧板能混合中继。

## 3. 去重、重试与背压

- 目标交付键：source + destination + source_boot + message；Room/epoch 由当前配置隔离。记录长度和 CRC，重复内容只重发 ACK，不再入箱；同身份不同内容拒绝。
- 中继键增加 kind，记录 attempt 位图。同次尝试经不同路径到达只转发一次；后续重试可以重新经过同一中继，使丢 DATA 或丢 ACK 后能恢复。
- 目标缓存 32 条、30 秒；中继缓存 32 条、10 秒。满表不驱逐有效记录，而是拒收/背压，等待源有限重试。保证只限当前会话和缓存窗口，不是跨重启恰好一次。
- 每个源仅 1 条在途消息，1200 ms 间隔，最多 4 次尝试。正常调度约 4.8 秒返回 TIMEOUT；超时表示结果未知，不能据此断言目标没有收到或执行。
- ACK 表示目标固件收件箱接纳。PC 必须另行 POLL、核对源/boot/message/bytes，再 CONSUME。设备执行完成应由后续应用层返回独立结果。

这些参数优先保证低频控制和文本事件的可验证性，不是文件吞吐配置。目标 32 条/30 秒缓存会限制持续新消息速率（长期约 1.07 条/秒/目标，突发另受 8 项收件箱限制）；中继 DATA/ACK 也占用去重槽。文件和高频游戏状态不能直接沿用此可靠通道参数，后续应使用有界滑窗/序号窗口、批量确认、流控和独立快照更新语义，再重新测容量，不能仅增大重试次数。

## 4. USB 与验证工具

所有业务命令使用 TRILINK/3，nonce 由调用方提供：

```text
TRILINK/3 INFO nonce
TRILINK/3 CONFIG nonce ROOMHEX EPOCHHEX MAC1 MAC2 ... MAC6
TRILINK/3 TABLE nonce
TRILINK/3 SEND nonce DESTMAC HEXDATA
TRILINK/3 POLL nonce
TRILINK/3 CONSUME nonce SRCMAC BOOTHEX MESSAGEHEX
TRILINK/3 RELAY nonce 0
```

MAC 是不带冒号的 12 位 hex，Room/epoch 是非零 8 位 hex。CONFIG 允许 1–6 个唯一 MAC 并包含本机。相同配置幂等；同 Room 的新 epoch 可更新成员，需无本地在途发送且无未消费收件箱。旧 epoch、同 epoch 改成员及切换 Room 拒绝；当前换 Room 需要明确重启后重新配置。更改 epoch 会清除拓扑/去重并重新收敛，但不会重置 source message。配置仅 RAM 保存，没有假装实现分布式提交。

TABLE 输出 count、local、neighbors、members、routes。local/下一跳为规范化成员表的 1-based 下标；routes 的每项为 `next/hops`；本机或当前不可达为 `0/0`。INFO 输出在途状态、结果与计数。USB 命令上限 384 B、回复 512 B，保留原有每秒 20 条接收限制；诊断工具自身不超过每端口每秒 10 条请求。

在明确设备数据口、关闭其他串口占用后，手动运行：

```powershell
# COM_A/B/C 是占位符，替换为已核对的原生 USB 数据口，不是 CH340/CH343 烧录口。
C:\Espressif\tools\python\v5.5.5\venv\Scripts\python.exe -B .\tools\mesh_probe.py --ports COM_A COM_B COM_C --epoch 00000001
```

工具支持 2–6 端口，顺序不表示路径。不扫描串口、不烧录。写 CONFIG 前检查所有端口身份、在途消息、未读收件箱与配置冲突；不会为测试清空别人的数据。配置后有界等待路由、验证所有有序端对之间的字节和 boot/message，以及 132 B 最大负载；只有本次确认的数据才 CONSUME。

配置跨板并非原子操作，中途拔线可能留下部分板已配置，工具将报错而非自动重置；应核对 INFO/TABLE 后人工重试或重启。脚本不会擅自改 relay 状态，也不会断言“某一中继关闭后所有端必断”：存在直达/备选路径时应保持可达。旧 chain_probe.py 仅保留作 v0.7 历史工具和共享有界串口读取器。

## 5. 容量与所有权

route 状态有编译期及 map 检查，预算不超过 4 KiB，不动态分配，不新增路由任务。沿用 RX 固定池 16 槽/3360 B；节点任务是路由、收件箱、USB 业务状态唯一写入者。无线回调只复制入池。异步 TX 拷贝自持有数据，普通/ACK 队列 8/4 项、过期 600 ms；USB 命令/回复各 4 项，收件箱 8 项。

实际 BIN、静态 DIRAM、各栈帧和 source manifest 见 VALIDATION 与构建 receipt。静态剩余 RAM 不等于运行时可用堆；必须继续观察 Wi-Fi 分配、栈高水位和长期丢包。BSP、ESP-IDF 5.5.5、N16R8、XMC 补丁与 factory 分区未变。

## 6. 已完成与下一门槛

软件已有任意成员自动中继、六节点五跳、菱形重复路径、换路重试、拓扑过期/不对称链路、缓存背压和 128 个确定性拓扑图测试。图模型不等于真实 RF/RTOS 验证。

客户端 Room 插件 1.1.0 限制最多 6 人（包含创建者），在请求、邀请及实际批准时检查；排队批准不能超额，拒绝不丢申请；正常退出按加入顺序继承，正式房间降为一人解散。这仍是模拟 Room 后端，真实硬件模式不开放尚未实现的入群操作。

下一步：真实 Room 管理协议与唯一 USB 会话服务 → 将提交成员表转换成传输 epoch/roster → 设备双闪的应用回执与权限 → 三板真机跨范围、各板轮换中继、断链恢复和 30 分钟压力测试。未入群节点的发现/申请必须走独立准入控制面，不能把 CONFIG 当审批，也不能把临时失联当自动退出。leader 意外掉线先暂停成员变更，自动选路不等于已有分区安全的 leader 选举。
