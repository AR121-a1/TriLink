# 0.16.0 second-board flashing and native CDC acceptance

> Public copy, redacted for publication on 2026-10-15. Board1/Board2/Board3 are stable public labels, not transmitted MAC addresses. Physical MAC/USB serial/PnP instance identifiers, local COM assignments and backup hashes are withheld. Original private records remain unchanged. Historical local evidence paths are not public downloads.

Date: 2026-10-14, Asia/Shanghai. Public board label: `Board2`.

Flashing, independent Flash verification, 35-second startup observation and native CDC read-only communication passed. NCM failed to start on this host with Code 10, matching the first board's observed failure. The existing unpatched 0.16.0 image was used on both boards.

## Target and preflight

The only attached device was CH343 [port-redacted], instance `USB\VID_1A86&PID_55D3\[instance-redacted]`. Live ROM identity confirmed ESP32-S3 QFN56 rev0.2, 40 MHz crystal, GD Flash `c8/4018` 16 MiB and embedded AP PSRAM 8 MiB.

The first security query failed with `Packet content transfer stopped (received 9 bytes)`. Its log was retained. One retry at 115200 baud succeeded and confirmed the same MAC, Secure Boot disabled and Flash Encryption disabled. No writing occurred before this successful check.

The three images and all 130 input hashes matched build `20261012-173202-b0407e2b`. No source, SDK or partition change was made.

## Startup and native CDC

The bounded UART helper reset once and captured 35 seconds. It then closed [port-redacted]. Observations:

- App 0.16.0 / IDF 5.5.5, GD 16 MiB Flash, PSRAM 8 MiB self-test passed.
- TinyUSB CDC+NCM and ESP-NOW channel 6 initialized; controller reached CORE_READY.
- One ROM boot, six core samples from 5498 to 30498 ms; no panic, watchdog, brownout or repeated boot observed.
- Internal free heap 198667 B remained stable; minimum 166416 B, largest block 122880 B.
- PSRAM free/min 8385916 B, largest 8257536 B.
- Lowest reported stack margins: USB 988 B, node 1808 B, TX 1928 B, controller 1388 B. These are short idle observations, not all-task/load peaks.
- Peers 0/6, radio TX success reached 60, fail/timeout/drop/ownership error 0. No multi-board delivery was established.

After the user moved the cable to native USB, composite serial `Board2` matched the flashed board. CDC appeared as **[port-redacted]** (`VID_303A&PID_4011&MI_00`). With DTR=false, the reused bounded probe passed HELLO, CAPS, ROOMGET page 00 and SEARCH. CAPS reported firmware 0.16.0, boot `D2A00091`, 132 B route body, six neighbors, six members and RGB mask 01. SEARCH returned zero peers.

The cable move power-cycled the board, changing boot ID from UART `462304FC` to CAPS `D2A00091`. No CREATE/JOIN/LEAVE/KICK or RGB enable/pulse was sent. The CDC port is closed; the desktop client was not launched.

## NCM outcome

Network interface `USB\VID_303A&PID_4011&MI_02\[instance-redacted]` matched Microsoft `usbncm.inf` / `UsbNcm`, driver 10.0.26100.9444, but reported Code 10/status `0xC0000483`. The NCM adapter was Not Present. DHCP and web access were not reached.

This reproduces the first board's host-side failure with the same firmware. The probable TinyUSB divisor compatibility issue and upstream repair evidence remain in the [first-board diagnostic record](HARDWARE_0160_BOARD1_20261014.md). No compatibility patch, driver installation, route edit or second flash was performed in this board2 operation.
