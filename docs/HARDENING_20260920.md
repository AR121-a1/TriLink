# 2026-09-20 底层与已有功能加固

开发范围：修复真实 Room / RGB 的版本、重复请求和 UI 生命周期边界；不增加新业务、不改变 BSP/SDK/引脚/USB 接口、不烧录。开发验证后，按用户要求仅同步客户端源码、测试和文档到 GitHub；下述固件源码与镜像仍仅保存在本地。
固件升级为 **0.9.1**，`trilink.hardware-room` 升级为 **0.1.1**，其余客户端插件版本及产品 `0.14.0-local` 保持不变。

## 本轮修复

| 问题 | 修复与边界 |
| --- | --- |
| 旧界面命令可修改较新的 Room | 本地 Room 管理命令同时匹配 room/incarnation/revision/term。过期操作拒绝，刷新后重新选择 |
| 延迟的旧 LEAVE 可能移除当前成员 | 无线 LEAVE 也要求当前 revision/term；不重放旧退出意图 |
| RGB 最近一项缓存被其他任务替换后，旧请求可能重新执行 | 给最多六个当前成员保存已接受应用序号水位。较旧请求拒收；当前任务的同内容重复仍可返回结果 |
| 完成结果可能被矛盾的失败回执覆盖 | 驱动完成/失败/拒绝终态不再改变；超时未知可被迟到的真实终态解决，但不会被迟到的“受理”重新变成等待 |
| Room 变更后仍显示旧请求进行中 | 当前等待中的 RGB 显示结果未知，不把成员切换当作执行成功 |
| 查询失败后旧成员仍可选 | 本批回复验证通过后统一更新；通信或格式失败清空失效成员/房间并提示刷新。名字超长、未选择目标等本地输入错误不发命令，也不清除有效状态 |
| 自动刷新不断取消用户选中项 | 成员、房间、申请、邀请及邻居按稳定身份保留选中项；记录消失时不自动改选其他对象 |
| 手动暂停后还继续读取整批页面 | 暂停使当前批次失效，正在进行的单次事务结束后，不再查询余下页面 |
| 相同 RGB 结果反复刷日志 | 只在应用ID或结果变化时记录；切换端口重置 |

## 占用与扩展性

RGB 新增六项固定水位记录，无动态增长、无后台新任务，不扩大 Room/邻居数量。水位是当前成员会话内的易失状态，离开/重启后不提供持久化防重放或身份认证。
最终固件镜像805584 B，较前版增加352 B；静态DIRAM149095 B，仅增加120 B。Room仍4464 B、最大项目单函数栈帧512 B。完整构建包标识 `20260920-085546-21a06627`，运行时堆/栈峰值尚未实测。
保持一个 RGB 执行槽，不增加无限结果缓存；过旧请求可能只被拒绝、不能找回历史结果，因此不承诺永久 exactly-once。
PC 继续使用统一 `IHardwareCommandService` 串口所有权；真实模块与模拟模块分离，仍可独立构建/替换。未为未来文件业务新增通用框架。

## 验证方法

先新增失败用例，观察到旧 Room 命令造成成员错误变更，以及旧 RGB 操作使 fake 驱动执行数从3变4；修复后分别通过。

- C主机测试12组：**93138 断言**，包含 Room319、Room/RGB 集成93；断言数量不是独立场景数量。使用真实协议/bridge/route代码，radio/LED为fake。
- 客户端：核心136、模块53、桌面30，HardwareRoom **37 项**。覆盖第4次失败仍运行、第5次暂停、恢复、无效回复、保留选择、输入校验、关闭和手动暂停停止批次。
- 正常、空状态、失效/暂停状态的自动渲染图位于 `artifacts/tests/Release/ui/`；均为测试夹具，不是真实设备截图。
- 固件完整镜像、容量和源文件清单由 `tools/build_local.ps1` 生成，精确数值以对应 `verification.json` 为准。
- 原 SDK/BSP 与引脚不变，开发验证阶段未执行联网下载、烧录或GPIO动作。后续GitHub同步仅包含客户端源码、测试和文档，不包含固件或二进制Release。

## 保留的限制与下一步

真实三板跨范围通信、LED光学效果、USB插拔、用户交互桌面尚需实测。RGB仍默认禁用，第三块板引脚未确认前禁止启用。
未增加自动故障选举、持久化共识、异常掉电恢复、请求历史存储、认证加密或文件业务。下一轮应专门完善入群确认/申请过期协调：当前申请端超时而leader仍保留待审批项时，迟到批准仍可能造成待确认成员；实机批准前应确认申请端仍显示等待。不能把本轮加固描述成完整故障恢复协议。
