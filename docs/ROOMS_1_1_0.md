# Room 插件 1.1.0：六成员容量边界

2026-09-16。仅更新 Room 功能插件，保留桌面壳、串口适配器和模块管理边界。

- 最多 6 人，包含创建者/本机，而非本机加 6 个远端。
- 申请和邀请检查容量，搜索视图满员时禁用相应操作。
- leader 实际批准时再次检查：多个待审批请求不能把人数冲到 7；失败不改变 revision、成员、副本或待审批请求。空出位置后可以重试原申请。
- 普通成员仍可邀请，但不能批准。正常退出仍按加入顺序继承；正式 Room 降为一人解散，新建一人 Room 仍可等待加入。
- 没有添加虚拟硬件节点；演示仍为三台模拟电脑。Room 后端仍是 SimulatedNetwork，硬件模式继续禁用未实现的真实入群。六人成员测试不等于六板无线实测。

构建与软件验证：

```powershell
.\tools\build.ps1                 # 全量编译与各模块/桌面自动化测试
.\tools\build.ps1 -PluginId trilink.rooms  # 独立更新 Room，现已强制运行 Core 回归
```

本轮全量构建通过；最终 Room 定向更新通过 Core **136 项、0 失败**、插件依赖/manifest 校验和 UI 冒烟生成。全量流程中模块 **53 项**、桌面模式与生命周期 **30 项**通过；UI 冒烟图已检查，Room 版本为 1.1.0。X 隐藏、托盘恢复/退出语义未改。上述是自动化窗体验收，未声称真实交互桌面/硬件验收。

产物仍为 `artifacts/Release/TriLink.MinClient.exe`，插件位于 `artifacts/Release/plugins/trilink.rooms/`。定向构建不需重建桌面壳；已运行实例需重启加载新版插件。测试日志和截图在 `artifacts/tests/Release/`，未混入运行目录。

固件 v0.8 已有六成员自动路由传输底座，但 CONFIG 不是 Room 同意入群。接续开发必须先补真实 Room 管理消息和 USB 会话所有权，再将提交成员表下发为 roster/epoch；传输路径变化与成员离开不能混为一谈。
