## 使用入口

1. 先托盘退出旧实例，再使用整套九插件、共享契约/宿主、profile更新PC2，不混旧DLL。0.14.4入口`artifacts/NodeConsole-0.14.4/TriLink.MinClient.exe`、ZIP`artifacts/packages/TriLink-NodeConsole-0.14.4-Release.zip`已校验22项/158299B、91输入及三定位快捷方式，SHA见交付收据 (historical local evidence, not included: `../artifacts/tests/NodeConsole-Timing-0144/delivery-receipt.json`)。冻结构建不是部署入口；历史0.14.3包保留，22项/154881B与哈希见[队列记录](QUEUE_CLOSURE_0143.md)，不含本轮两项修复。
2. S3 的**原生 USB 数据口**连接电脑，主窗口识别成功后直接使用首页真实 Room / RGB 区域；也可通过“扩展模块…” → “真实 Room / RGB”打开独立窗口。CH340/CH343 是烧录口，不是该业务口；无数据口时页面显示连接指导，不产生模拟节点或无效写命令。
3. 已识别且可见页默认只读初刷新；活动leader约2秒、其他约5秒轻量更新，active邻居SEARCH至少15秒追加一笔，手动“刷新设备与 Room”合并完整请求。调度不是实时保证，前台可让后台在一笔I/O返回后让位。身份/操作所需状态有效后合法业务可入队，不因后台忙全部禁用；第五自动失败清light/full残留再停timer，须显式手动启动清零并立即读。手动暂停/换设备/设备事件不偷偷恢复旧调度。顶部USB发现另计；仍人工核对固件统一0.10.2，能力筛选不校验对端空口版本。
4. A 创建 Room；B/C 在附近 Room 中选中并申请加入。A 刷新待审批列表，逐个同意。**同意后先等待成员确认再进行下一次成员变更**。普通成员也能邀请；接受邀请仍需 leader 审批。
5. leader 正常点“退出”后按加入顺序继任；已形成多人 Room 降为一人时解散。退出的leader本机保留旧快照重播10秒，期间不能创建或加入其他Room；看到“正在重播退出公告”时稍后刷新，期限后恢复。刚创建的一人Room仍可被发现。关闭PC客户端不等于退出Room；S3继续持有内存副本，前提是保持供电。
6. 每个目标设备都需在自己的电脑上手动确认“GPIO48 / WS2812 GRB 单灯”后启用 RGB。**启用是许可，不会点灯**；三号板尚未确认，不可默认启用。重启后回到禁用状态。
7. 测本机时点专用“本机青色双闪”，不必选择成员。未入Room时须确认创建一人真实Room，并按实际状态复核后执行；新建Room保留，不会为测试自动退出。CREATE前后同一物理目标的重复点击仍在途去重；该规则不放宽Room/boot/权限复核。已有Room时使用现有Room，不改变成员关系。测试远端才选择有效成员，点“目标青色双闪”；远端必须自行批准硬件许可。
8. 请求排队后自动跟踪同一应用ID终态，最多12秒预算并快速复核ROOMGET00。不重复提交闪灯命令，未知不当成功；用户可以暂停读跟踪，但暂停不能保证板端已受理的灯效被撤销。当前仅低亮度双闪，不是灯效编辑器。
9. 如提示“RGB驱动故障，已停用”，本机启用按钮不能清除故障；先检查接线，协调退出Room后重启故障设备。故障时不保证物理LED熄灭，不能只用界面上的禁用状态判断灯已灭。

## 发现不等于Room连接

板端保持供电后启动广播HELLO，此后每500ms广播、每1秒向已发现邻居单播心跳；最多6个物理邻居，2秒未更新则过期。发现不等待PC/DTR，但现固件仍要求本机原生USB驱动初始化成功才启动node。固件自动注册对应MAC为ESP-NOW peer，不是用户批准逻辑Room或经过认证的连接。

本端原生USB SEARCH已看到`Board2`、RSSI=-51dBm，只是本端附近设备发现证据；SEARCH不提供对端能力/boot，旧HELLO兼容节点也可能出现，不自动认定支持Room/RGB。列表显示“发现/附近、能力未验证”，不显示“已连接/已加入”。至少两块板供电、核对当前固件，再由申请端经原生USB提交JOIN、leader同意及成员确认后，才成为Room成员。另一电脑接CH343不能替代原生USB业务口。本机能创建一人Room和执行许可灯效，但不能独自验证邀请他人、审批、踢人或leader继任。

## 真正运行在哪里

`PC 模块 → 共享 USB 命令适配器 → 本机 S3 Room 引擎 → ESP-NOW → 对端 S3`

Room 的成员快照存放在各 S3 RAM，PC 不承担一致性协调，不依赖同一个 PC 进程中的全局对象。
leader 是当前唯一成员变更发起者，但不是唯一信息持有者。成员顺序、启动标识、room/incarnation/revision/term 均进入快照。
房间发现、邀请和审批走有界广播控制面；RGB 走已有成员路由的数据面，允许其他成员中继。
现有 `trilink.rooms` 仍为模拟演示；主窗口真实模式内嵌 `trilink.hardware-room` 的同一功能工厂，旧模拟按钮只在明确开启演示后显示。嵌入页与独立模块均读取 S3 状态，不把模拟副本混作真实 Room。

## 按钮与状态说明

- 页面区分无设备、不兼容、需要刷新、就绪、忙和失效，并在状态区说明恢复方法。无设备/不兼容不执行业务，也不消耗通信失败预算；重复同一错误不会刷屏。
- 创建/申请/接受邀请需要最新成功刷新、当前未入房、无等待/未知票据、无退出重播；名称按 1–23 个 UTF-8 字节校验。选择相应 Room 或邀请后才启用入口，满 6 人不可加入。
- 普通成员可邀请附近非成员及退出；审批、拒绝、踢出由 leader 执行。leader 尚未收到成员确认时不开放成员变更和退出；已经同意但待确认的申请不能重复批准，仍可拒绝。leader 不能踢自己。
- 入群结果未知时只提供原票据的显式重试；不会自动另建 Room 或重放写命令。每个业务按钮有前置条件 Tooltip，状态区补充角色、同步、等待和硬件许可说明。
- RGB 启用前弹窗写明COM/MAC与接线条件，确认期间设备变化则取消；许可与执行分别有按钮。已许可且无故障时才允许本机双闪，专用入口不依赖成员选择；未入Room时先明确确认创建。远端须在其自己的管理端批准。排队/受理时阻止重复发送，启用/禁用后读回真实状态。
- 自动结果跟踪绑定原QUEUED应用ID、设备MAC、room/incarnation/revision/term与目标成员boot。RGBRESULT匹配后再以ROOMGET00核验当前会话；变化/失效/取消/超时为未知，不把旧终态贴到新Room，也不重新发灯效。12秒是读跟踪预算，不是强行中断已开始OS调用的硬截止。
- 有可用状态的合法动作可进入每页前台FIFO，最多8等待项、在途另计，重复动作去重；无身份/权限/选择/许可仍不可执行。点击捕获名称、目标、设备与Room/票据，改变选择不会改变旧意图；出队真实核验，过期或变更取消。审批/拒绝等待6秒、其他15秒，不保证都赶上固件8秒窗口；审批空口仍仅带MAC，PC核验不能消除TOCTOU。
- RGB在途去重按generation/local MAC/physical target识别，与CREATE前后Room/incarnation/boot或名称变化无关；这些变化仍由执行前置复核处理，不允许旧上下文写入。不同物理目标及RGB禁用可排队，完成后新的明确请求可重新提交。
- 同端口换身份/能力/拔插、暂停和销毁清除待项与两类合并刷新标志；不偷偷恢复旧扫描。“清空待执行”仅撤销尚未提交的队尾，已调用USB服务的命令可能在途，不能撤销或保证未执行。取消/超时未知不自动重放，通信异常保留完整堆栈诊断。

## 回执含义

| RGB 状态 | 含义 |
| --- | --- |
| 排队 / 0 | 本机已受理发送，不证明对端已执行 |
| 1 | 目标执行器已受理 |
| 2 | 目标 LED 驱动完成双闪及清零调用；不是物理亮灭的光学反馈 |
| 3 | LED 驱动返回失败 |
| 4 | 目标未启用 RGB，或执行器不能接收任务 |
| 5 | 10 秒内没有得到终态，结果未知；不要当作成功或保证未执行 |

链路 ACK 只表示应用收包路径接收了数据，绝不直接显示“闪灯成功”。USB 命令超时也标注未知，客户端不自动重放写命令。
应用 ID 与路由 ID 分开；最近一次相同应用请求可重发回执而不再次闪灯，内容冲突拒收。不是持久化、无限期 exactly-once 保证。

## 资源与轮询

- 单一串口所有者协调扫描、搜索、业务；没有新增第二个独立串口连接器。
- 每个业务事务先复核 MAC 与能力，再发送带 nonce 的命令；本机事务间隔至少 150 ms，USB 固件仍限制 20 行/秒。
- 页面同一UI线程异步pump串行调度，前台FIFO优先、后台意图合并；不是新增线程或串口连接。leader轻量约10笔/2秒意图，其他活动成员约3笔/5秒意图；active SEARCH≥15秒追加单笔。隐藏不发起周期读，暂停/失败5次/换设备/销毁保持停止；计时间隔不保证实际每次完成。
- 第五次自动失败清light/full合并意图后关闭自动与timer，不让Drain执行残留第六批恢复就绪；手动启动清零立即读。正常/20×同场景fake复测验证此停止边界，不证明真实设备长期时序。
- 一次RGB任务的终态跟踪是有界读操作，不等于永久后台轮询，也不绕过手动暂停或设备切换；专用本机入口只在用户确认后进行必要的创建/执行写入。
- 手动完整刷新与未入Room相关发现仍约22笔I/O；申请区可先经状态锚点核验发布，前台写后先读ROOMGET00，重更新交后台。页查询非原子快照，后台旧批次不能覆盖新前台权威状态；public RefreshAll拒绝绕过pump并行批次。共用USB不等于跨页全局业务事务锁。
- RGB仍固定原ID/会话12秒跟踪，phase5为应用结果未知：清相关队尾并使状态失效，不继续关联写、不自动重发，也不计作USB传输失败；驱动失败/拒绝不当成功。
- 固件 Room 静态状态预算 6 KiB，RGB 仅一项任务，独立 worker 栈 3072 B；不创建文件缓存、HTTP 服务或音视频栈。
- 当前ESP32-S3配置为单灯、无DMA，由一个worker串行提交，最多一个RMT事务在途；提交不等待队列空位，完成等待每事务100 ms。这个期限不代表整个双闪任务100 ms，也不是硬件实测时延。
- RGB任一驱动故障锁存至重启，禁止后续set/clear/refresh和重新分配执行器；首次清理失败时保留资源并停止重复删除。空闲worker等待任务队列仍可阻塞，此时没有在途操作。

## 明确限制

- 最多六成员含本机；物理邻居另有六项，不能把邻居等同于成员。
- 缺少成员确认时冻结成员变更，不自动故障选举。正常退出有顺序继任；leader 掉电、成员重启后的自动恢复尚未实现。
- 副本是易失内存，不是持久化共识；审批队列、邀请与执行记录也不是持久化日志。成员重启可能使旧 Room 冻结，当前实验恢复方式是全部参与设备重启后重建。
- 退出后的最终状态重播窗口为10秒，期间保留旧快照；长期分区不保证自动恢复。未经认证的实验网络：MAC/CRC/nonce 不等于身份认证或加密，不用于生产权限控制。
- RGB 单灯固定 GPIO48；最高分量32，当前按钮使用8。禁用阻止后续执行，但首次启用后驱动引脚资源可能保留到重启。RMT有界完成等待与故障清理适用于当前S3/无DMA配置，不能推广为所有芯片/配置的故障时序保证。驱动失败后的物理灯态未知，单板重启仍需先协调Room状态。
- 文件、文本消息和游戏业务尚未接到真实 Room；原始测试 `CONFIG/SEND` 在实际 Room 激活期间被隔离。
- 未实测吞吐、无线丢包下时延、堆峰值、三号板 LED、三台 PC 的真实 USB 生命周期。
