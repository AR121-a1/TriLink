## 房间操作规则

1. 创建者是初始 leader；新建的一人房间为等待状态，仍允许加入。
2. 申请加入不会立即成为成员，必须由当前 leader 同意。
3. 任意成员均可邀请；接受邀请后仍进入审批流程。
4. leader 可以拒绝申请、踢出成员；普通成员没有这些权限。
5. leader 正常退出后，由剩余成员中最早加入者继任。
6. 房间曾达到两人后进入正式状态；正式房间剩一人时解散。
7. 突然掉电或长期网络分区后的自动继任/恢复尚未实现；正常退出的丢包恢复限于有界公告窗，退出整个客户端也不会保存房间到磁盘。
8. Room 最多 6 人（包括创建者/本机）；满员不接受新申请或邀请，待审批不能超额批准，空出位置后可重试。
9. 真实Room的退出leader在10秒公告窗内不能创建或加入，以保留旧快照重播；普通成员不会因该本机leader保护而增加公告等待。

## USB 与使用方式

不需要硬件时，以 `--demo` 启动，切换电脑 A/B/C 演示。普通启动等待真实设备，不自动选择模拟 A；主窗口的模拟 Room 按钮在真实模式保持禁用。真实操作在“扩展模块 → 真实 Room / RGB”，需要新固件能力位；存在入口不等于已完成三板验收。

串口仅探测 TriLink 描述、Espressif VID `303A` 或 `TRILINK_PORTS` 指定的候选端口；候选身份只是筛选条件，必须通过nonce握手才能认定节点。真实模块通过ROOMGET读取本机S3的附近Room与当前成员，PC不建立一致性副本，也不把主窗口模拟房间按钮用于真实准入。

暂停针对后台自动扫描；用户点击“搜索设备”是独立的显式操作。进程退出会释放插件资源；Windows 关机和注销不会被 X 隐藏逻辑拦截。当前没有安装器、系统服务或默认开机自启动。

真实模块的状态轮询默认关闭，手动开启后每5秒单飞刷新，连续5次失败暂停。RGB故障提示对应本机USB状态，不表示所有成员均故障；故障后检查接线并协调退出Room再重启，界面显示停用不保证物理LED熄灭。

## 运行与交付

- 目标环境：Windows、.NET Framework 4.8；离线构建使用本机 Visual Studio Roslyn 与参考程序集。
- 本机运行目录：`artifacts/Release/`，需整体保留 EXE、依赖、profile 和插件 DLL/清单。
- 测试、截图和日志：`artifacts/tests/Release/`；它们不属于源码仓库中的预编译交付物。
- 双击托盘或“打开 TriLink”恢复窗口；托盘右键“退出”结束程序。
- 没有已部署的互联网中继、VPN、商业服务器或云端数据存储依赖。

源码中具体入口见 [架构说明](ARCHITECTURE.md)，协议字段见 [USB 与 Room 契约](USB_AND_ROOM_CONTRACT.md)，后续验收见 [开发计划](ROADMAP.md)。
