# 0.14.1 上位机实际功能闭环

日期：2026-10-09。产品 `0.14.1-local`，桌面 `1.2.0`、串口 `1.2.2`、真实 Room/RGB `0.3.0`，Host API `1.0`。本轮保留 S3 原生 USB 数据口，不修改固件，不上传 GitHub。

## 本轮解决的问题

旧首页的搜索/创建/退出属于模拟 Room 控件，真实功能藏在扩展模块里；未识别数据口时真实页面没有可操作状态，用户只能看到灰按钮。本轮把真实功能页直接嵌入首页，隐藏真实模式下的模拟操作。仍复用现有插件与单个 USB 服务，不新增后台进程或第二套串口所有者。

完整已有操作入口：刷新、创建、申请加入、接受邀请、邀请附近设备、leader同意/拒绝/踢出、退出、入群未知结果手动确认，以及本机RGB许可和目标闪烁回执。按钮不会为了可点击而绕过固件前提；提示和ToolTip解释尚缺设备、刷新、选中项、leader权限、容量或同步状态。

## 实际使用

1. 从旧客户端托盘右键“退出”。按 X 只是隐藏，直接打开新EXE会恢复仍在运行的旧实例。
2. 打开 `artifacts/NodeConsole-0.14.1/TriLink.MinClient.exe`，或同目录“启动 TriLink（真实硬件）.lnk”。须保留整套DLL、plugins和profiles。
3. 连接 S3 **原生 USB 数据口**。CH340/CH343是烧录/日志口，不承载本版控制协议。候选口先完成HELLO身份/能力核对才算已连接。
4. 识别后点击“刷新设备与 Room”；读取成功后业务按钮按当前快照启用。空闲板可创建，看到其他房间后选中再申请，看到附近非成员后选择再邀请。
5. leader选中待审批条目可同意/拒绝，选中非本机成员可踢出；普通成员也能邀请。最多6人含本机。收到邀请仍需leader审批。
6. 如需持续状态刷新，手动启动页面中的“状态轮询”。顶部USB轮询只管端口发现，两者独立；USB扫描异常或页面状态通信失败各有连续5次暂停门，手动恢复清零。单个候选口HELLO不匹配/超时按“未识别”诊断去重，不等同于整轮扫描异常；无设备或输入不满足不计为页面通信故障，不刷重复错误。
7. 命令超时/结果未知时先刷新，不自动重放变更；入群未知仅用明确的重试确认入口。leader退出后可能重播旧公告10秒，等待并刷新再建/入房。
8. RGB默认关闭；确认板型/接线后由用户显式启用。发送排队不是对端执行成功，应看执行结果；RGB驱动故障不自动恢复或重试。

## 验证与证据

完整Release、Debug各 **934** 项：Core136、SerialLifecycle126、HardwareRoom94、Modules64、Thunder444、Desktop34、内置选择/输出保护36。九份插件清单/profile、真实/模拟布局、最小窗口、托盘生命周期和运行目录门通过。Serial与HardwareRoom业务回归使用fake；Thunder联机测试是PC UDP/loopback，不是ESP32游戏。

真实设备为 COM_PORT，`Board1`，本地固件v0.10.2。原生USB测试驱动实际主表单按钮，并核对主页面与嵌入页使用相同真实发现/命令服务：

- HELLO核对身份与Room能力；完整读取Room各页及RGBRESULT，没有模拟替代。
- 读到空闲状态，创建临时 `UT1009-5c7d7a`，读回真实一人Room并启用退出。
- 点击退出，读回成员清空、无活动Room；出现10秒退出公告提示，符合固件现有规则。
- 当时附近节点为0，不把此前UART心跳发现当作本次多板业务证据。
- 没有RGB指令、GPIO执行、烧录、分区或固件修改；测试结束已退出临时Room并释放自身服务。

证据分开保存：`artifacts/tests/NodeConsole-20261009/Release/`、`Debug/`、`NativeClosure/`。NativeClosure含原始日志、ready/created/left截图及测试驱动源码/二进制；该驱动会创建/退出空闲板测试房间，不是普通运行入口，也不自动纳入无硬件构建。

这是 **自动化表单 + 真实单板 USB** 验收，不证明用户交互桌面可见/可点击；审批/邀请/踢出、正常leader继承、物理RGB亮灯仍需至少两块板/多电脑分步实测。文件传递、板端资源包与P2P复制、板端游戏和固件OTA未因本轮GUI修复而实现。
