## 已收束的两个软件问题

RGB底层改为RMT非阻塞提交，每个在途事务的完成等待限100 ms。当前ESP32-S3采用无DMA单灯配置，一个worker串行提交，一次最多一个事务在途；100 ms是单次等待期限，不是整个双闪任务或端到端时延。任何驱动故障锁存本机RGB停用状态至重启，界面会显示故障。首次清理失败后保留执行器资源，停止后续set/clear/refresh，不重复删除或分配新执行器；物理LED可能保持故障前的灯态，不能保证熄灭。空闲worker等待任务队列仍可阻塞，此时没有在途操作。

Room原leader正常退出后保留10秒旧快照公告。此前立即创建新房会覆盖唯一快照，首次交接包丢失时剩余成员可能永远等待旧leader；现改为公告窗内拒绝本机CREATE/JOIN，旧快照继续重播，期限后恢复。客户端显示“正在重播退出公告，请稍后刷新”。该保护不增加快照缓存，不实现自动故障选举，也不保证超过公告窗的永久分区恢复。

Room空口仍为opcode2，与0.10.0相同；本次补充的RGB故障位bit6（64）和退出公告位bit7（128）属于本机USB状态，不改变无线协议。能力位筛选不代表无线版本兼容，三板验收仍统一使用0.10.1；0.9.x不能混入opcode2 Room。

## 操作与恢复

1. 从完整`artifacts/Release/`启动客户端，通过“扩展模块 → 真实 Room / RGB”操作；X隐藏到托盘，托盘右键退出才结束进程。
2. 正常申请后，leader同意仅发出OFFER。等待申请者CONFIRM和成员名单同步后，再进行下一次成员变更；“入群结果待确认”只允许恢复原leader通信后重试原票据，8次后再次暂停。
3. leader退出后，原leader本机等待退出后的10秒公告期限并刷新，再创建或加入。剩余成员按加入顺序继任；已形成多人Room降为一人仍解散。
4. RGB默认关闭，逐板核实GPIO48 / WS2812 GRB单灯后才启用。出现故障提示时，切换启用不能清除故障；先检查接线，协调退出Room后重启该设备。单板重启会丢失Room内存状态，不能把它当作无影响的灯效恢复操作。
