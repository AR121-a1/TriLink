# 雷霆战机 0.2.0（本地多人扩展）

定位更新：本版为PC联机/渲染参考，不是板端任务包。新主线先实现S3轻量回合游戏，PC仅输入/展示，见 [节点控制台新定义](NODE_CONSOLE.md)；不将C#引擎与512KB像素画布直接下放MCU。

2026-10-05。基于官方 `thunder-game` 分支 `3cb3fda` 的独立本地优化，支持单人练习与2–6人合作像素射击。原始归档112个文件经Git换行规范化后均匹配远端blob哈希；本次修改未合并主干或上传。当前联机通过IPv4 UDP；ESP32游戏桥接尚未实现，不把loopback测试标为跨实体电脑或三板验收。

## 使用

完整构建后，从主窗口“扩展模块…”选择“雷霆战机”，点击“打开功能”。WASD / 方向键移动，默认自动射击，空格加强射击。每人三条命、独立战机/友弹配色，阵亡后旁观；所有玩家共享得分，最后一名存活者阵亡才结束。

2–6台电脑连接同一个可信实验局域网（不要开放公网端口；token不是认证或加密）：

1. A选择本地端口（默认47830）和本局人数（2–6），创建合作房。
2. 其余电脑填写A的局域网IPv4与该端口，再加入。每台电脑自己的本地端口可以都为47830。需要自行允许该UDP端口，本工具不修改防火墙。桌面宿主保留同一Windows会话单实例；同机多人验证使用独立测试进程，各进程端口不同，并非同时打开多个正式客户端。
3. 房主是P1；其余P2–P6按握手分配，不需手填席位。全部所选人数完成握手才开局；房主显示到齐进度，已连接玩家等待，不提前运行自己的世界。
4. 游戏房主独立于TriLink Room leader，不修改S3 Room成员。对端端口/人数在会话期间锁定；要修改先停止。
5. 停止、关闭或隐藏联机窗口会离开游戏并释放端口；任意玩家离开/失联将结束整局，所有人重新建房/加入。单人隐藏暂停，恢复继续。只有游戏画布有焦点时接收操作。
6. 所有电脑必须使用本版GameWire v2；0.1.0的双人v1不兼容。不支持中途加入、自动重连或房主迁移。

默认打开功能只绘制静态预览，不创建 socket、定时任务或联网；启动游戏后才创建会话。没有网络发现广播、互联网中继、UPnP、音效文件或图像资源包。

| 插件 | 服务 / 依赖 | 职责 |

| `trilink.thunder` 0.2.0 | 消费 `trilink.module-features`、`trilink.game-link` | 按需视图、固定六席引擎、v2协议和多人会话 |

Host API 保持 `1.0`，新增契约属于加法扩展。新功能需首次完整构建使共享 DLL、profile 与插件配套；以后可分别重建两个插件。游戏只引用 Abstractions，不引用桌面、串口或 Room 插件实现。

```powershell
.\tools\build.ps1

.\tools\build.ps1 -PluginId trilink.game-link
# 当前客户端仍占用 Release 时，可先构建独立 Debug 目录进行验证。
```

游戏更新与其他模块一样，托盘退出后重启生效。导入和模块启停沿用 ModuleStore 的校验、独立包目录与原子保存规则；不能禁用仍被游戏依赖的传输提供者。

## 资源预算

| 项目 | 固定上限 / 行为 |
| --- | --- |
| 逻辑更新 | 30 Hz、整数坐标，同 seed + 同逐 tick 输入产生同一状态 |
| 网络更新 | 10 Hz，每次提交最多 3 tick；渲染不驱动网络帧率 |
| 实体池 | 固定6玩家、24敌机、64友弹、48敌弹、16爆炸；本局只激活1–6玩家；满池丢弃新效果/实体，多人发射顺序轮换避免低席位长期抢槽 |
| 引擎动态数组 | 实体字段约5KiB，另有对象头；消费输入数组或偏移，Step无逐tick分配 |
| 像素画布 | 固定 320×400×4 B，约 500 KiB；复用 Bitmap、Graphics、画笔和字体 |
| 成员与补发缓存 | 固定最多5个peer；120tick×6B=720B历史，约4秒；逐peer ACK，最慢peer约束恢复窗口 |
| 应用消息 | 常规房主帧24+3N B、单个队友输入24B；最大补发24+16×6=120B；适配器上限128B |
| 常规应用载荷 | N人合计10×(N−1)×[(24+3N)+24] B/s；2人540、3人1140、6人3300B/s，另加UDP/IP、握手/补发 |
| 接收工作 | 每次 Update 最多 16 数据报；适配器单次最多丢弃 8 个无效报文 |
| UDP 缓冲 | 应用接收 129 B，OS 收发缓冲各请求 8192 B（实际值由 OS 调整） |
| 空闲 / 关闭 | 不运行游戏 timer；关闭释放 socket、timer 与 GDI 资源 |

这些是代码上限和载荷预算，不是整进程内存、CPU、无线吞吐或端到端延迟的真机测量。运行时、WinForms 双缓冲及 socket 内核资源另计。

## 协议与同步

`GameWire`为版本2，整数little-endian。24B头：magic `54 46`、version、type、session u32、token u32、tick u32、input sequence u32、count u8、input u8、playerCount u8、playerIndex u8。Frames后跟count×playerCount字节，先tick后玩家；count=1–16、playerCount=2–6。输入位left=1/right=2/up=4/down=8/fire=16。字段语义、边界与共享接口见 [实施约定](THUNDER_MULTIPLAYER_PLAN.md)。

Hello携带每位加入者独立token；Start分配session、种子（tick）、人数和席位；Ready确认。房主维护每席独立端点/token/就绪/输入序号/ACK与通信时间；到齐后才提交世界。等待期Start/Ready心跳持续，重复握手不重置引擎。Input的tick是该队友已应用的最高tick，sequence拒绝过期操作；报文必须符合本局人数和发送者席位。

房主每100ms采样所有玩家最新输入，推进3tick，记录固定历史，并按每席ACK独立发送连续批次。队友只消费覆盖下一个tick的批次，重复跳过，缺口不推进。每席输入300ms未更新采用中立输入；5秒无有效通信或最慢peer超过历史窗口则整局终止，不跳过已提交tick。未获席位的加入者12秒连接截止；已获席位等待其余人数到齐，不消耗恢复窗口。

GameOver后继续每席确认与最后tick补发，直到停止/离开。Bye是尽力通知，丢失时由超时释放余下会话。无中途加入、自动重连、主机迁移、快照重同步或跨进程存档；100ms批次尚无本地预测，不是竞技低延迟模式。

引擎规则和输入批次定义是同步协议的一部分；改变敌机生成、碰撞、伤害或 tick 规则时必须同步升级 `GameWire.Version`，让不同规则的客户端在握手前明确拒绝报文。

## 后续 ESP32 接入

保持游戏引擎和 `GameWire` 不变，新增替代 `trilink.game-link` 的服务提供者，实现 `IGameLinkFactory / IGameLink`：

1. 适配器规范化自身目标地址（如 MAC），接收时使用相同标识；`Open` 的数字由适配器解释为本地端点 / 通道。当前 UDP 地址规则不进入游戏协议。
2. 与现有共享 USB 访问所有者协调，定义专用、有界的游戏发送 / 接收桥接及能力位。当前固件与 `IHardwareCommandService` 只允许 Room/RGB 命令，不能把游戏数据塞进这些命令。
3. S3将来仅路由最高120B游戏报文；画面、实体模拟、每席ACK与补发历史留PC，不下发资源文件，也不能另建独占COM争用扫描器。六人每个房主批次发给五个peer，应用载荷与队列需真机确认。
4. 原生 CDC / ESP-NOW 上测量双向 10 Hz 的吞吐、延迟、丢包和队列峰值。若实际链路预算更低，应调整双方约定并升级协议版本，不静默改变确定性 tick。
5. 原服务提供者和 ESP32 提供者只能启用一个，沿用宿主的重复服务保护。游戏房主由游戏会话选择，Room leader 仍仅负责成员关系。

当前 token 用于区分会话和误投报文，不提供认证或加密；首版面向实验局域网。

## 验证

`tests/TriLink.Thunder.Tests` 覆盖确定性、碰撞与池容量、协议拒绝、丢包 / 重复 / 重排恢复、握手重试、终局补发、会话隔离、断线 / 历史耗尽、socket 边界与释放，以及视图渲染和隐藏 / 关闭生命周期。测试使用内存故障适配器及 IPv4 loopback，不接真实 COM。

本地多人验证结果另记于 [本次核对与优化](THUNDER_REVIEW_20261005.md)。本节末尾0.1.0的489项为下载基线历史，不是0.2.0的验收结果。游戏测试固定desktop+demo+safe-mode，只验证本次内置插件，不执行用户导入覆盖。

构建将截图输出到 `artifacts/tests/<Configuration>/ui/ui-thunder-*.png`，日志写入 `logs/thunder-tests.log`。独立进程 UDP 测试验证2/3/6个游戏会话世界一致；跨实体电脑、ESP32无线和用户桌面操作仍须单独验收。

历史0.1.0记录（非本次多人结果）：游戏分支以主干串口1.2.1、真实Room/RGB0.2.1为基线，原Debug构建共489项检查。此次下载后原Release基线也通过489项；多人0.2.0请以本次核对文档和新生成日志为准。正式启动本次输出前，从托盘退出旧客户端；单实例宿主不会因为双击新目录EXE就替换已运行的旧DLL。
