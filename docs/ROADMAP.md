# 后续开发计划

基线为 v0.13 客户端。以下均为计划，不表示功能已实现；不承诺具体日期。优先补齐真实链路，再增加承载在链路上的应用。ESP32 固件不在本仓库发布，固件侧的事项在本文中作为外部联调条件记录。

## 阶段与验收

| 优先级 | 目标 | 客户端工作 | 外部条件与完成标准 |
| --- | --- | --- | --- |
| P0 | USB 真实识别闭环 | 固定 HELLO/DEVICE/SEARCH 解析、错误分类、端口访问协调与取消 | 配套固件提供原生 CDC ACM；插拔、无响应、错误 nonce、端口忙均有实测记录 |
| P0 | 三电脑独立节点身份 | 将本地身份与远端邻居分离，真实 profile 不创建 A/B/C 假节点 | 三台 PC 每台只拥有自己的节点；发现结果来自实际设备 |
| P1 | 接入真实传输服务 | 新增稳定传输接口与 USB 适配插件，Room 通过该接口收发 | 三板 ESP-NOW 路由命令与有界回包可用；客户端不直接假设无线帧大小 |
| P1 | 真实 Room 状态同步 | 传送申请/审批/邀请/成员事件，operation_id 去重、term/revision 校验、缺口请求快照 | 三独立进程副本最终一致；乱序、重复、丢包注入测试可重现 |
| P1 | 失联与网络分区 | 定义故障检测、成员资格、仲裁与恢复协议 | 拔掉 leader 后行为可预测；孤立节点不能自行审批产生双 leader |
| P2 | 纯文本与资源摘要 | 文本、资源 ID、名称、长度与摘要；请求原始数据前显式确认 | 三机互发 UTF-8，超长数据被限制或分片，重复包不重复显示 |
| P2 | 按需文件传输 | 分片窗口、ACK、重试上限、流控、断点、整文件哈希与取消 | 传输内容校验正确；取消/失败释放文件句柄；总内存与临时文件有上限 |
| P3 | 小游戏示例 | 增加轻量应用插件，游戏房主与 Room 管理 leader 分开 | 低频小游戏三机可玩；记录时延、吞吐、重传与队列占用 |
| P3 | 唤醒能力实验 | 定义可选唤醒提供者，不耦合 Room 与文件服务 | 按具体电脑、电源与 USB 唤醒条件逐项验证；不把一般笔记本视为必然支持 |

## 开发顺序与约束

1. 先建立 `local node / remote peer / room replica` 的明确数据模型，再连接真实 Room 事件。当前 `SimulatedNetwork` 保留为可重复测试实现，不直接扩张成同时管理三台真机的全局对象。
2. 先定义应用层消息与传输契约，再决定 S3 上的紧凑二进制编码。现有 USB 文本契约负责控制面；大文件字节不塞进无边界的日志或文本命令。
3. 固件回调只处理有界数据入队，PC 保存文件主体；最大帧长、窗口数、队列深度和超时由真实测量及双方能力协商确定。
4. leader 管理成员准入，资源发布者负责其数据；游戏的权威主机由游戏会话自行选择，不自动等同于 Room leader。
5. 每个新插件先增加清单和契约、模拟适配与失败测试，再接设备。保持单插件编译、重启更新与发布目录隔离。

## 分区与恢复设计门

不能仅靠“失联就选最早加入者”处理无线故障。正常退出顺序继任已经存在；异常失联需要另外定义已确认成员集合、term 分配、事件提交条件以及少数分区的只读/等待行为。不能让仅剩单机把失联误判为全体同意解散，或让两个分区同时拥有准入权。

## 每阶段留下的证据

- 可复跑的正常、空数据、超时、取消、断连与恢复测试。
- 三机联调记录中的软件版本、固件版本、节点标识与实际接线；发布前移除个人机器信息。
- 吞吐、端到端时延、重传次数、队列峰值及设备堆内存的测量结果；测试前不填估计值冒充实测。
- 自动化截图、真实交互桌面检查、真机链路检查分别记录。

## 暂不进入主线

公网 NAT 穿透、中继服务器、VPN、USB 虚拟网卡、热卸载第三方 DLL、音视频和全去中心化游戏一致性暂不并行推进。这些目标会改变链路、权限或可靠性假设，应在三机控制与文本传输闭环后单独立项。
