# 显式扩展模块（本地 0.14）

扩展状态：可扩展。主窗口右侧 **扩展模块…** 是显式入口，没有 ESP32 也能使用。管理窗口单独关闭；主窗口 X 仍隐藏到托盘，真正重启必须先从托盘“退出”。

## 操作

| 操作 | 实际行为 |
| --- | --- |
| 模块详情 | 名称、ID、包版本、本次运行版本、下次启停、待重启、能力、依赖、加载目录 |
| 启用 / 禁用 | 校验整个启用集合后保存，本次代码继续运行，下次启动改变 |
| 打开功能 | 按需创建模块注册的功能窗口，后台服务模块没有可打开的视图 |
| 导入 / 更新 | 选择可信包的 `plugin.json`，确认来源与哈希，复制到独立目录 |
| 撤销本次配置变更 | 恢复本次启动时的选择，不删除留存包 |
| 恢复内置模块 | 选择随客户端发布的原始包和 profile，不再使用导入版本 |
| 安全恢复 | 完全退出后用“启动 TriLink（安全恢复）.lnk”或 `--safe-mode`，忽略自定义配置 |

默认六模块：Room、串口、模拟、桌面、扩展管理、文本工具。前五个是当前桌面依赖集合，不能任意禁用；禁用会破坏其他模块依赖时拒绝保存。文本工具可独立启停，不是占位按钮。

`trilink.text-tools` 提供 UTF-8 字节数、SHA-256、Base64 检查。没有轮询或联网，仅在打开时创建界面，点击计算时处理最多 16,384 个 UTF-16 代码单元。**它不是聊天或无线传输，真实网络文本传输仍待实现。**

## 包与更新规则

第一版仅支持 `plugin.json` + 单个托管 DLL，不接受压缩包、脚本、额外依赖 DLL、原生库或资源目录。面向 .NET Framework 4.8，入口实现 `ITriLinkPlugin`。外部依赖不会自动下载或复制。

- 校验 schema、Host API、版本、文件名、输入容量、SHA-256、受保护程序集名、启用程序集重名、依赖缺失 / 服务冲突 / 环。
- 配置 / 清单 ≤ 64 KiB，DLL ≤ 16 MiB；启用 ID 和导入映射分别最多 64 个。
- 拒绝路径穿越、Windows 非法文件名 / ADS 和重解析路径，导入目标使用程序生成的 GUID。
- 确认绑定清单和 DLL 哈希的指纹，复制后重验；源包变化时拒绝应用。
- 新模块默认禁用，同 ID 更新保留启用状态；允许用户显式导入旧版回退。
- 有缺失依赖的新包可以先导入，但不能启用；不自动拉取或开启依赖。
- 读取程序集元数据不运行插件入口。入口类型和运行逻辑要到下次启动才能验证；失败时回滚启动并提示安全恢复。
- **完整性哈希不是可信签名，插件与客户端同权限；仅导入可信 DLL，当前不提供恶意代码隔离。**

## 持久化

```text
artifacts/Release/
  plugins/<id>/plugin.json + DLL       原始内置包，GUI 不覆盖
  profiles/desktop.profile.json        原始组合，GUI 不覆盖
  module-data/
    desktop.json                      下次启动的 enabled + packages 映射
    desktop.json.previous             上一次配置备份
    packages/<GUID>/plugin.json + DLL  独立导入包
```

启动使用原始 profile 加 `module-data/<profile>.json` 覆盖；安全模式跳过覆盖。配置先验证、写临时文件、原子替换，成功后再更改管理服务状态。没有运行中覆盖 DLL、热卸载、自动重启或额外后台服务。

便携运行目录需当前用户可写；无写权限会显示操作失败，不会要求提权或静默写到其他位置。

导入失败、更新或撤销后可能留存未被选择的包，加载器只读映射指向的版本，不扫描全部 `packages`。第一版没有删除 / 自动清理功能，也没有留存包总量配额；文件会占用磁盘，后续需补充可验证的离线清理。

安全模式只恢复导入包 / 用户选择造成的失败，不修复原始宿主 DLL、内置插件或系统运行时损坏；原始文件损坏须从完整 Release 备份恢复。安全模式只开放恢复内置操作，恢复后正常启动再管理。

## 扩展性

| 边界 | 职责 |
| --- | --- |
| `ModuleContracts.cs` | `IModuleManagementService`、`IModuleFeatureRegistry`、快照 DTO、按需功能贡献 |
| `PluginHost/ModuleStore.cs` | 启动与管理共用配置解释、验证、文件存储，不创建 UI |
| `trilink.modules` | 管理服务、功能注册表，无定时器、不操作串口 |
| `trilink.desktop/ModulesForm.cs` | 展示快照、提交命令、确认来源、拥有功能窗口 |
| `trilink.text-tools` | 可运行的独立示例，只依赖稳定契约，不引用桌面实现 |

Host API 1.0 是加法扩展，旧接口方法不变；新插件声明新服务依赖，旧宿主缺少服务时明确拒绝加载。当前未抽象插件进程隔离、依赖版本区间和任意资源包，不承诺无限兼容。

新建独立功能模块：

1. 参照 `src/Plugins/TriLink.Plugin.TextTools/` 新建程序集、模块 ID、入口类及唯一功能 ID。
2. 只引用共享契约和所需框架库，清单声明 `trilink.module-features`。
3. `Configure` 注册工厂，用 `context.Defer` 回收注册；工厂在桌面 STA 按需调用，控件由窗口释放。
4. 编译并写入 DLL 的 SHA-256；源码中的无哈希清单不能当安装包。
5. GUI 导入 → 选择启用 → 托盘退出 → 重新启动 → 打开功能。无需修改宿主或桌面源码。

```csharp
var lease = context.GetRequired<IModuleFeatureRegistry>().Register(
    new ModuleFeature {
        Id = "example.tool.inspect", ModuleId = context.PluginId,
        Title = "数据检查", Description = "本地工具"
    }, () => new MyToolView());
context.Defer(lease.Dispose);
```

开发内置模块可运行 `tools/build.ps1 -PluginId trilink.text-tools`，开发构建覆盖内置包，须先退出客户端。GUI 导入是另一条不覆盖内置文件的更新路径；若已导入同 ID 包，正常启动优先使用导入版本，要测试重编的内置包应先恢复内置或使用安全模式。

2026-10-01起，构建脚本的UI smoke和桌面生命周期回归自动固定`desktop + --safe-mode`，直接验证内置组合，既不删除导入包也不恢复/覆盖用户配置。同ID导入覆盖、损坏配置和构建参数的独立回归位于`tools/test-built-in-smoke.ps1`；普通启动仍按用户组合工作，两种验收不能混为一谈。
