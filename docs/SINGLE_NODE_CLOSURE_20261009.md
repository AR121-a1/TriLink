# 0.14.2 单节点执行与上电主动发现

日期：2026-10-09。产品 `0.14.2-local`，桌面 `1.2.1`、串口 `1.2.2`、真实模块 `0.3.1`，Host API `1.0`。本轮保留原生 USB，不修改或烧写固件；板端仍为现有本地 v0.10.2。前一轮0.14.1/934项与单板创建退出记录见 [历史上位机闭环](CLIENT_CLOSURE_20261009.md)，不是本轮双闪证据。

## 单节点与多人操作的边界

“至少一个节点可使用”应当落实为真正的单节点执行路径，不是加入虚假成员或让所有按钮无条件成功。

| 功能 | 最少真实参与者 | 单节点行为 |
| --- | --- | --- |
| USB识别、状态读取、RGB许可 | 1块S3＋本机控制台 | 可以独立操作；许可开启不等于点灯 |
| 创建/退出Room、本机双闪 | 1块S3 | 一人Room有效；本机目标无需另一个节点或列表选择 |
| 上电邻居发现、无线peer注册 | 1块S3即可启动，发现对端需2块 | 不依赖PC控制；没有对端时正常显示0邻居 |
| 入群、邀请、审批、踢其他成员、远程RGB、leader继任 | 至少2个相关真实节点 | 不伪造申请或对象，也不绕过leader权限 |
| 文本检查、游戏练习、PC插件管理 | 本机电脑 | 已有PC功能保持；不是板端资源包/ESP32游戏 |

当前固件的RGB命令要求活动Room且目标为成员，包括本机。无Room直接RGB会被拒绝，所以本轮在客户端提供明确的“创建单机 Room 并双闪”确认：真实创建一人Room并保留，不暗中创建后隐藏、不自动退出。已有Room时按钮为“本机青色双闪”，直接使用本机MAC。

## 操作闭环

1. 从旧本机客户端托盘退出，再打开0.14.2整套运行目录。
2. 连接原生USB数据口，识别后页面可见时自动只读初刷新，并受控刷新状态/邻居。不会自动创建Room、申请加入或打开RGB许可。
3. 核对所选COM/MAC、GPIO48/WS2812 GRB接线，点击“允许本机 GPIO48 RGB”。读回许可后才显示已允许；许可按钮不会发RGB任务。
4. 点击本机双闪，不必选成员。有Room时直接执行；无Room时显示真实Room名称及创建/保留的确认，拒绝时不写设备。
5. 只发送一次RGB，保存QUEUED操作ID，按同ID自动读取0等待/1受理/2驱动完成/3失败/4未许可或忙/5超时未知。排队不是执行成功。
6. 回执和终态上下文核对有界；MAC、Room/incarnation、版本/成员启动标识、视图代次变化后标为未知，不自动重发。暂停/退出只阻止后续查询，不声称即时中断已开始的串口事务。
7. 手动停止、换设备或连续5次通信失败后不会因界面显示/设备事件偷偷恢复；显式启动可恢复。附近节点仅标记无线发现和RSSI，不用“已连接”冒充认证或Room准入。

驱动完成证明实际驱动调用及板端执行回执，不是光学测量。物理灯是否双闪应另外人工确认。RGB驱动故障不能靠许可开关自动恢复，需协调Room后检查/重启。

## 板端主动发现：已有实现，不是PC模拟

现有node任务在启动时广播HELLO，之后500ms一次；向已知邻居每1000ms单播HEARTBEAT。有效HELLO进入固定6项邻居表，并注册ESP-NOW peer；2秒没有更新即过期移除。信道固定6；不是AP关联、认证连接或经过CONNECT/ACCEPT的会话。

CH343可给板供电，发现与心跳不等待PC/DTR。不过固件启动仍要求原生USB驱动初始化成功；CH343不承载该版Room控制协议。另一电脑要在旧客户端操作申请/审批，仍应连接其S3原生USB数据口。

本轮只读SEARCH已发现另一电脑的 `Board2`，RSSI约−51dBm；本机为COM_PORT、`Board1`。这是本端无线发现记录，未据此宣称对端固件能力、双向业务连接或入群成功。SEARCH当前不提供对端能力/boot；仅HELLO兼容的更老固件可能被发现但不支持Room/RGB，不能自动当成可入群对象。
